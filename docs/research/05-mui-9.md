# Research: `@mui/material` 7.3 → 9.5 (+ `@emotion/react` / `@emotion/styled`)

Date: 2026-11-06. Sources are primary only (mui.com guides/blog, mui/material-ui GitHub, npm registry metadata).

## TL;DR

- **There is no Material UI v8.** MUI moved Material UI "straight from v7 to v9 (there is no Material UI v8, like there is no v2)" to realign with MUI X ([MUI v9 blog](https://raw.githubusercontent.com/mui/material-ui/master/docs/pages/blog/introducing-mui-v9.md), line 175). Verified independently:
  - `npm view @mui/material@8.0.0` returns E404.
  - The GitHub releases list goes v9.5.0 … v9.0.0 and the alphas/betas, with no `v8.x` tag ([releases API](https://api.github.com/repos/mui/material-ui/releases?per_page=100)).
  - `https://mui.com/material-ui/migration/upgrade-to-v8/` returns 404.
- The official guide is a **single consolidated v7 → v9 guide**: "This guide explains how to upgrade from Material UI v7 to v9" ([Upgrade to v9](https://mui.com/material-ui/migration/upgrade-to-v9/)). The blog also says "For a consolidated upgrade path from Material UI v7, follow the Upgrade to v9 migration guide" ([Material UI v9 blog](https://raw.githubusercontent.com/mui/material-ui/master/docs/pages/blog/introducing-material-ui-v9.md), line 202).
- **Recommendation: jump 7.3 → 9.5 directly (no hop). GO**, as a small, low-risk change.
  - Only **one** MUI component family is in use (`Select` + `FormControl` + `InputLabel` + `MenuItem` + `ListSubheader`), plus `ThemeProvider` and `createTheme`.
  - **Zero** hits for the removed APIs.
  - Two things need verification, not code changes: the SelectMui specs under jsdom, and the Cypress selector.

### Confirmed breaking-change matches

1. **`Select` `MenuProps` (verified safe, no change needed).**
   - Location: `SelectMui.tsx:66`: `MenuProps={{ sx: { maxHeight: '60vh' } }}`.
   - v9 removes `MenuListProps`, `PaperProps` and `TransitionProps` from `Menu`, including when passed via `Select`'s `MenuProps` ([guide, "Menu props"](https://mui.com/material-ui/migration/upgrade-to-v9/), raw lines 1434-1476).
   - We pass only `sx`, which is untouched. **No fix needed.**
   - Heads-up: the codemod `npx @mui/codemod@latest deprecations/menu-props <path>` exists if this is ever extended ([codemod README](https://github.com/mui/material-ui/tree/HEAD/packages/mui-codemod#menu-props)).
   - Optional safety check: running `deprecations/all` is a no-op on this codebase.

2. **Menu / MenuList `selectedMenu` focus management. Affects accessibility, keyboard and tests; confirmed relevant.**
   - Location: `SelectMui.tsx:56-75`. `Select` renders its options in a `Menu` with `variant="selectedMenu"`.
   - Behaviour change ([guide, "Menu and MenuList"](https://mui.com/material-ui/migration/upgrade-to-v9/)):
     - Arrow, Home/End and character navigation now move DOM focus and also set `tabindex="0"` on the focused item, with `-1` on the previously focused one (roving tabindex).
     - `autoFocus` on `MenuList` no longer sets `tabindex=0` on the `List`.
     - Keyboard navigation now supports `MenuItem` inside a `Fragment`.
     - `ListSubheader` and `Divider` no longer need `muiSkipListHighlight`.
     - Custom children with `role="menuitem"` that don't wrap `MenuItem` are unsupported.
   - Our grouped rendering in `SelectMui.tsx:42-45` returns an **array** of `[<ListSubheader/>, ...<MenuItem/>]`, not a Fragment.
     - It is not a custom `role="menuitem"` child, so it is not broken by this change.
     - `ListSubheader` is non-interactive and should now be skipped natively.
     - **Fix: none in code. Manually verify keyboard navigation over grouped options (screen reader and keyboard) in the Storybook story and in `StationsSelector`.**
   - Net effect is positive for WCAG AA (a single tab stop, correct roving focus).

3. **jsdom behavior change. Affects specs.**
   - The guide states `process.env.NODE_ENV === 'test'` checks are replaced by feature detection / user-agent sniffing, and that layout-less DOMs such as jsdom and happy-dom are auto-detected ([guide, "jsdom support"](https://mui.com/material-ui/migration/upgrade-to-v9/)).
   - Affected specs (vitest, `environment: 'jsdom'`, `vite.config.mts:29`) that render `SelectMui` with `REPLACE_INPUTS_WITH_MUI=true`:
     - `src/app/components/pages/howToInstall/instructions/InstructionsContainer.spec.tsx:7-10,21-61,173`. They use `getByRole('combobox', {name})`, `getByRole('listbox', {name})` and `userEvent.selectOptions`.
     - `.../stationsSelector/StationsSelectorContainer.spec.tsx:345` (flag set).
   - **Fix: none known; run these specs after bumping.** The guide says "This change shouldn't impact most users, but it might lead to unintended CI changes", so treat it as a verification step.
   - No MUI-specific test setup exists in `src/test/setupTests.ts` (only the `matchMedia` stub and jest-dom), so nothing there depends on removed behaviour.

4. **Cypress selector (verify only, not a documented breaking change).**
   - Location: `cypress/page_objects/howToInstall.ts:18-22`:
     - `div[role="combobox"][aria-labelledby="${label}"]`
     - `li[role="option"]`
   - It depends on MUI's rendered DOM and ARIA attributes for `Select`. The v9 guide does **not** list a Select DOM change for the `FormControl + Select` pattern, so this likely still works.
   - The only listed label change is `TextField select`'s `InputLabel` rendering a `<div>` instead of `<label>` ([guide, "TextField"](https://mui.com/material-ui/migration/upgrade-to-v9/)). We use `FormControl` + `InputLabel` + `Select` directly (`SelectMui.tsx:49-56`), which the guide says is unaffected ("does not affect `<InputLabel>` on its own").
   - **Action: re-run the Cypress howToInstall spec after the bump** (see `docs/research/10-cypress-16.md` for the Cypress upgrade plan).

5. **CSS-module overrides (verify only).**
   - Location: `SelectMui.module.css:1-18`. It targets only our own class names (`div.container`, `div.select`, `::before`).
   - It targets no `.MuiXxx-*` classes, so the removed deprecated class names (e.g. `iconFilled` → `.MuiSelect-filled ~ .MuiSelect-icon`) do not apply.
   - Visual-regression (Storybook/Chromatic) is the safety net; confirm there is no visual diff for `variant="filled"` Select.

## Accessibility / mobile touch / jsdom call-outs

- **Accessibility (net positive):**
  - Menu roving tabindex (see above).
  - `Backdrop` no longer sets `aria-hidden` by default (no `Backdrop` usage here; `Select`'s Menu uses a Modal-style backdrop that is invisible, and the guide does not flag a Select change).
  - The `Slider` and `Stepper` semantic changes do not apply.
  - The v9 blog says it focuses on "accessibility improvements, sx prop performance, and cleanup of deprecated APIs" ([v9.0.0 release notes](https://github.com/mui/material-ui/releases/tag/v9.0.0)).
- **Mobile touch:**
  - The `ButtonBase` Enter/Space click-bubbling change and the `Slider` pointer-event change do not apply to `Select`.
  - `MenuItem` is ButtonBase-based, but touch handling is unchanged in the guide.
  - Test the Select dropdown on real iOS Safari 17+ and Android Chrome: tap-to-open, 60vh scroll, and tap-to-select.
  - Safari ≥17 minimum applies (see Browser targets).
- **jsdom:** see item 3. Run `vitest` for the two specs above.

## Recommendation

**Direct 7.3.11 → 9.5.0. No hop, because there is no v8 and the official guide is a consolidated v7→v9 path. GO.**

Steps:
1. Bump `@mui/material` to `^9.5.0` in `package.json:29`. Leave `@emotion/react` (11.14.0) and `@emotion/styled` as they are; their peers are satisfied.
2. Run `npx @mui/codemod@latest deprecations/all src` (expect no changes).
3. Run `tsc`, ESLint and `vitest`. Pay particular attention to `InstructionsContainer.spec.tsx` and `StationsSelectorContainer.spec.tsx`.
4. Run the Storybook build and check the visual diff of `SelectMui` (filled variant, grouped options).
5. Run the Cypress howToInstall flow.
6. Manually test keyboard and screen-reader behaviour on the grouped Select, and on iOS Safari 17+.
7. Decide on the iOS < 17 support policy before rollout. The Select is behind the `replaceInputsWithMui` flag, so the rollout risk is already contained.

Caveats: I did not run an install or the tests (per instructions). The "no impact" conclusions come from grep plus the guide, and the jsdom and Cypress items are unverified until run.
